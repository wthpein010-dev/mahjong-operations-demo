# 运营后台 V1.7 接口对接需求及交接清单

版本：V1.7　日期：2026-10-11

这份附件交给阿福确认与完善现有系统接口。接口字段、权限、历史快照与幂等能力齐备后，由 Nirvana 接入后台并对接测试，再把核对后的 OpenAPI、样例、错误码及测试记录同步到 Apifox。

当前文件是开发参考与交接附件，没有发送给上述人员，也没有同步到远端 Apifox 项目。公开演示仅使用虚构数据；真实源接口、认证、游戏改动与财务接入仍待对接。以下49项业务路径是统一参考路径，阿福可以提供现有源路径与字段映射，不要求原系统直接改名；最后6项是公开演示数据库接口。

## 统一字段与调用约定

- 金额使用整数分，奖励比例使用整数基点（100基点等于1%），房卡数量为整数；界面负责展示格式。
- 时间使用带时区的ISO 8601，统计日按Asia/Shanghai；事件发生时间、更新时间、同步时间分别返回。
- 业务接口成功响应为 `{data,requestId,meta}`；分页使用page从1起、pageSize默认20且最大100、total；历史增量另用稳定cursor和nextCursor。
- 服务端认证后获取账号、角色、授权区、服务对象及permissionVersion。前端role/account/regionIds参数不能授予权限；查询、详情、关联跳转和导出均重校验。
- 写请求携带Idempotency-Key、requestId、修改原因及版本。重复相同请求返回原结果；相同key不同请求体拒绝，版本变化返回409。
- 区域、代理、茶馆、客服与订单使用稳定ID。事件记录发生时regionId、agentId、teaId、ownerType、serviceSupportId与rewardRateVersion，不能用当前关系反算旧账。
- 异步写操作返回syncStatus和businessRequestId；pending不等于已生效。超时先查原结果再复用原请求号重试。
- 茶馆、玩家、房间、对局、充值退款、房卡余额和历史转卡只读。本清单无转卡、退款执行、奖励发放、玩家资产调整、强制解散接口。

## 错误与环境

400 BAD_REQUEST；401 UNAUTHENTICATED；403 FORBIDDEN；404 NOT_FOUND（兼顾对象不可见）；409 VERSION_CONFLICT或DUPLICATE_REQUEST；422 VALIDATION_ERROR；429 RATE_LIMITED；503 SOURCE_UNAVAILABLE。响应含code、message、requestId、可选字段错误details；不得返回密钥、完整敏感资料或不可见对象名称。

阿福提供测试/正式环境、各源路径、鉴权方式、权限账号、限频、历史起点、分页和增量方式、缺口及技术联系人。OpenAPI中业务接口的api.example.invalid是占位地址，必须在真实环境资料到位后替换。


## 认证与会话

### API-01 后台认证

- 方法与路径：`POST /api/v1/auth/login`
- 提供与接入：阿福提供或完善源接口；Nirvana接入并对接测试。
- 请求字段：loginAccount、credential、可选一次性验证码；凭据不得写日志。
- 响应字段：accessToken、expiresAt、accountId、roles、authorizedRegionIds。
- 鉴权与权限：认证登录按现有账号系统；不要求已有token；现有后台账号系统验证启用状态，不采集公开访客凭据。
- 分页：非分页接口；未列出的分页参数不适用。
- 历史与版本：不保存历史密码或token。
- 对接状态：待阿福确认并完善现有系统接口；Nirvana接入测试待源接口就绪。
- 错误：统一错误码；本项重点为409版本/幂等冲突、422业务约束、503源系统不可用。
- 样例：请求 `{"loginAccount": "demo-hq", "credential": "EXAMPLE_ONLY_NOT_A_PASSWORD"}`；成功响应可参考OpenAPI中data/requestId/meta样例，字段定义以本项响应列为准。

- 鉴权与权限：Bearer认证与服务端权限校验；总部详细；负责人仅本区完整性摘要；技术凭据不返回业务端。
- 分页：page从1起，pageSize默认20、最大100；total和可选nextCursor。
- 历史与版本：各源独立游标、历史起点、缺口与回执版本。
- 对接状态：待阿福确认并完善现有系统接口；Nirvana接入测试待源接口就绪。
- 错误：统一错误码；本项重点为403对象越权、404不可见对象、503源系统不可用。
- 样例：查询 `?page=1&pageSize=20` 仅适用于分页接口；详情以对应对象ID代入路径；成功响应可参考OpenAPI中data/requestId/meta样例，字段定义以本项响应列为准。

## 公开演示数据库接口

本组不连接真实账号，不接受客户端选定Cookie ID。首次GET读取分配HttpOnly匿名Cookie，尚不创建沙盒快照，mode仍为reference；首次POST仅为既定Cookie身份创建快照。成功GET/POST/DELETE均返回sessionId，它是Cookie token的SHA-256指纹（64位小写十六进制），不是Cookie或授权凭据，不能单独授权。POST/DELETE携带X-Demo-Session并由浏览器携带Cookie，同时校验同源Origin；头缺失或非法返回428 SESSION_REQUIRED，指纹与当前Cookie不符返回409 SESSION_CONFLICT且不含revision。POST另用数字If-Match校验revision，冲突返回409 REVISION_CONFLICT及当前revision。DELETE删除本人快照并轮换匿名Cookie，返回reference基线、revision=0及新sessionId；旧标签页继续用旧指纹写入会返回409，必须重新读取。冲突后停止写入，可用独立恢复弹窗确认重新加载、丢弃未确认修改并核对最新数据。清Cookie或更换浏览器不能找回旧沙盒。

### API-50 取得当前访客沙盒或公共基线

`GET /api/v1/demo/state`。无请求体；首次读取分配HttpOnly匿名Cookie，不创建沙盒；返回data、revision、mode和sessionId。state成功返回revision、mode、sessionId，GET/DELETE另含data；POST不重新签发Cookie。GET不创建个人快照。状态属于demo-only，不表示源接口已接通。

### API-51 保存当前访客沙盒

`POST /api/v1/demo/state`。JSON {data:完整读取状态}；X-Demo-Session为读取的sessionId，If-Match为数字revision；首次保存创建既定身份的沙盒。state成功返回revision、mode、sessionId，GET/DELETE另含data；POST不重新签发Cookie。权限为匹配Cookie和X-Demo-Session的本人匿名沙盒；错误与重新加载按上文处理。状态属于demo-only，不表示源接口已接通。

### API-52 恢复本人演示初始数据

`DELETE /api/v1/demo/state`。无请求体；带X-Demo-Session；删除本人快照并轮换Cookie，返回基线、revision=0和新sessionId。state成功返回revision、mode、sessionId，GET/DELETE另含data；POST不重新签发Cookie。权限为匹配Cookie和X-Demo-Session的本人匿名沙盒；错误与重新加载按上文处理。状态属于demo-only，不表示源接口已接通。

### API-53 数据库参考状态

`GET /api/v1/reference/status`。返回storage、dataset、tables、seeded。公共只读，不要求匿名Cookie；由公开示例实现，状态属于demo-only，不表示源接口已接通。

### API-54 数据库虚构实体分页

`GET /api/v1/reference/entities/{entity}`。entity、page/pageSize；返回items、total、page、pageSize。公共只读，不要求匿名Cookie；由公开示例实现，状态属于demo-only，不表示源接口已接通。

### API-55 下载参考OpenAPI

`GET /api/v1/reference/openapi`。也可访问/reference/openapi.json。公共只读，不要求匿名Cookie；由公开示例实现，状态属于demo-only，不表示源接口已接通。

## 阿福至Nirvana交接

1. 阿福逐项标记已有可复用、需要补充或暂不支持，补全真实路径、字段、必填、枚举、样例、错误、鉴权、区域权限、幂等、版本和历史快照；缺失历史字段明确列缺口。
2. 写接口先明确源系统责任，尤其同步开户、区域启停、代理迁区、服务绑定、配置回执和转卡限制。转卡限制须源系统拒绝，不能仅隐藏按钮；本新后台没有转卡写接口。
3. 阿福交付测试环境、角色/区域隔离的虚构测试账号、分页及增量样本、成功失败与超时回执、字段映射表和接口版本，交由Nirvana接入。
4. Nirvana记录接入状态、调用样例与requestId，核对开户归属、权限隔离、重复请求、迁区前后快照、奖励退款扣回、分页缺口及待同步状态。未修复问题回交阿福，修复后在同版本复测。
5. 接口和页面逻辑同步推进；源接口未就绪的页面继续标演示或待接入，不能把种子数据切换成生产数据。真实密钥通过环境配置管理，公开仓库只保留占位示例。
6. 核对后的OpenAPI及数据字典、错误码、环境说明、虚构样例、测试集合和变更记录进入Apifox；保存版本、时间、同步负责人和差异记录。缺少项目连接或写权限时交付可导入文件，状态保持待同步。

进入指定Apifox项目，选择导入数据中的OpenAPI并上传 `public/reference/openapi.json`；按接口ID和operationId核对49项待接业务契约及6项演示接口。正式业务环境、认证与变量须由阿福资料补全，公开演示URL只能用于演示组。后续更新先比对新增/变更/删除接口，不以全覆盖导入删除人工测试用例。
